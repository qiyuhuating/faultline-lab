# Portfolio guide

## 三分钟演示

1. **0:00–0:30**：`npm start`，打开实验台，说明三个 Worker 是三个独立进程，SQLite 保存真实任务。
2. **0:30–1:15**：点击 Crash，进入追踪。展示首次尝试 expired、新 Worker、新 token 和唯一结果收据。打开事件流中的 signal:SIGKILL。
3. **1:15–1:40**：点击 Dedupe，展示三次调用、一个任务和两条去重事件。区分内部实验调用与独立 HTTP 并发测试。
4. **1:40–2:20**：点击 Dead letter，等待死信后清除故障并重放。展示 generation 变化与保留的历史。
5. **2:20–3:00**：导出事件证据，用 CLI 校验；打开真实测试与微基准结果，说明单机与外部副作用边界。

## 可用于简历的项目介绍

**Faultline — 异步任务执行与故障恢复实验台**

技术栈：TypeScript strict、Node.js、浏览器原生 JavaScript ESM、SQLite WAL、HTTP/SSE、原生前端、Node Test Runner。

- 实现多进程任务执行引擎，通过事务领取、租约续约及递增 fencing token，拒绝过期 Worker 的结果提交。
- 实现持久化请求幂等、指数退避、死信重放与版本冲突处理；内置任务结果和成功状态使用同一数据库事务提交。
- 构建实时故障实验台与可导出事件链，完成 87 项核心自动化验证和 12 条负向类型契约，覆盖 240 任务 / 4 进程竞争及真实 SIGKILL 后接管。

需要展示性能时，可以补充：在记录的本机测试环境中，4 Worker 完成 500 个轻量摘要任务，用时 714 ms、生成 500 张结果收据。注明这是本机微基准，不写成生产 QPS 或性能 SLA。

## 不写到简历里的夸大说法

- 分布式调度集群、生产高可用、千万级任务。
- 所有外部副作用 exactly-once。
- 不可伪造的审计系统。
- 700 生产 QPS（该数值是本机内部提交与轻量处理微基准）。

## 新增面试演示

先展示 Zombie worker：新租约已完成，旧进程后来实际提交，被数据库以 STALE_LEASE 拒绝。随后展示 Lost response：POST 已经落盘但客户端拿不到响应，通过同一个请求键只读确认。最后解释报告为什么需要统一的 SQLite 读快照。

## 可展示的新增工程贡献

通过实际 SQLite 写锁和页配额复现并修复过期续租、写满后的错误覆盖、详情跨版本拼接及停机写入竞态；新增 13 项破坏性回归。面试时展示修复前失败记录、修复后的 61 项核心结果与 ADR 004，说明如何把疑点变成可复现的工程证据。

## v1.1.0：可讲清的架构演进

将兼任事务、持久化、状态机、实验与审计的 24.7 KB Queue 拆为 5.1 KB 组合入口；后端迁入严格 TypeScript，以判别联合约束租约和提交状态。通过旧数据库、跨模块回滚、负向编译与分层依赖验收验证重构，保留真实并发故障测试。面试时解释为何所有服务共享一个事务拥有者，以及为何查询 SQL 没有机械地包装成通用仓库。

## v1.2.0：把可靠性主张变成可运行规格

新增独立策略模型，以 128 个可复现种子执行 32,768 次状态操作，逐步核对真实 SQLite 中的租约、版本、尝试和收据；用故意错误的测试替身验证检查器能发现违规。完成七种真实 HTTP/进程故障、控制器重启和只读语义诊断。复现并修复删除全部事件后空链误判有效的问题，保留旧版本的原始失败证据。

演示时先展示只读诊断与下载报告，再解释为什么事件链完整不代表成功收据存在。最后运行一个模型种子并说明精确重现、覆盖范围与未覆盖的时钟/跨机问题。可以写进简历的贡献应对应这些实际文件和 CI 结果，避免用“最佳”“生产级集群”代替工程证据。
